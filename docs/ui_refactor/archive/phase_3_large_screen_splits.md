## Patterns reinforced across the 10 splits

1. **State retention rule.** State stays on the parent screen when `setState` + busy bools + `GlobalKey`s + `Notifier`s + `AnimationController`s + `ScrollController`s + focus state + sparkle launchers + messenger calls are involved. Extract the big `build()` body into a `StatelessWidget` with constructor params; pure helpers (static math) go to `*_geometry.dart` / `*_helpers.dart`.
2. **Per-card State retention** for collapsible/tab patterns: each panel/card with its own controller (`TextEditingController`, `TabController`) or `_completingId` becomes a `StatefulWidget`; State stays inside the panel, parent holds only screen-level busy flags.
3. **Action-handler vs child State split.** Handlers that need `setState(parent) + messenger.showSnackBar + provider mutation + sparkle launcher` stay as parent callbacks; the child widget just calls the callback.
4. **Constants / style lifting.** When the parent has a private `_Style` namespace used by N extracted widgets, lift to a public `XxxStyle` (or per-domain `XxxLayout`) in a single `*_layout.dart` / `*_constants.dart` file.
5. **Private-helper retention.** Privátní helpers used by exactly one widget (`_CloseButton`, `_Glow`, `_ClaimAllPill`, `_DaySectionSubheader`, `_SegmentButton`) go in the same file as their consumer — no separate file for a 30-LoC helper.
6. **Cross-file type lifting.** A private enum / typedef / data class used in ≥2 files gets promoted to public. Speciálně: data type for a callback signature (where the callback in the parent consumes a child-constructed type) belongs with the widget that constructs it, not back on the parent (`ActivityClaimRef → backfill_rows.dart`, `PlayerPreset → presets_panel.dart`, `SleepRange`/`StageColors`/`MapCollisionCircle`).
7. **Cyclic import workarounds.** Callback parameter instead of direct import (pattern: `CompanionChecklist.onOpenRelic` so a relic-detail sheet doesn't have to import the cosmetic-detail sheet that opens it).
8. **Sub-extraction when a widget grows > 400 LoC.** Pull header/footer/overlay chunks into siblings (pattern: `cosmetic_details_standard_body` → header + actions; `cosmetics_screen_card` → overlays).
9. **Per-slot provider subscriptions preserved** — overview-screen lesson: a multi-slot dashboard's per-slot `context.watch` model survives the extraction by letting each slot file own its own watch (don't fold them back into a screen-level `Selector`).
10. **Raster-budget invariants from Phases 0–1.3 applied uniformly during extraction.** Card-style widgets in a scrollable feed self-wrap `build()` in `RepaintBoundary`; `AnimatedSize` bodies get an inner `RepaintBoundary`; background images go through `DecorationImage(opacity:)`, never `Opacity` widgets; `BoxShadow(blurRadius >= 12)` is never animated on a growing silhouette.
11. **Dead-code cleanup during extraction.** If a field/param is threaded through a constructor but never read, drop it (sleep range field on `_ExpandedSleepBody`; same applied to body_screen's `range` parameter on `BodyMetricTrendCard` — kept here because it propagates to scope, but verified used by callers).
12. **Naming disambiguation when the `widgets/` dir is pre-populated** (cosmetics, social): prefix all new files + classes with the screen name (`cosmetics_screen_*` / `CosmeticsScreen*`, `profile_hero_*` / `ProfileHero*`) so they don't collide with the P1 sibling extractions in the same directory.
